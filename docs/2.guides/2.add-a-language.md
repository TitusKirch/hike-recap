# Add a language

Every user-facing string is in a locale bundle under [`locales/`](../../locales/) — components never hold one. German and English ship. Adding a language is one JSON file plus a tag in `tours.json`.

## Steps

1. **Copy an existing bundle.** The filename's stem is the locale name.

   ```bash
   cp locales/en.json locales/fr.json
   ```

2. **Translate every value.** The shape is fixed by the `Locale` type in [`src/i18n.ts`](../../src/i18n.ts) — `months` (twelve, in order), `stats`, `units` and `attribution`. Missing keys are a type error, so `pnpm typecheck` catches an incomplete bundle.

   The `stats` values read as verbs after a figure in the outro: `distance` follows the kilometres, `ascent` and `descent` follow the metre figures, `duration` follows the time.

3. **Name it in your `tours.json`.**

   ```jsonc
   { "locale": "fr-FR" }
   ```

   `loadLocale()` takes either the bundle name (`fr`) or a BCP-47 tag whose language subtag names one (`fr-FR`). An unknown tag falls back to the first bundle with a console warning rather than throwing — a missing translation should not stop a render.

4. **Re-ingest and check a frame.** The locale travels in the compiled JSON, so the scene will not see it until ingest has run.

   ```bash
   pnpm ingest && pnpm still 30 880
   ```

   Frame 30 lands in the intro card and 880 in the outro — the two places wording is on screen.

## Checklist

- [ ] `locales/<name>.json` exists and every key from the `Locale` type is translated
- [ ] `pnpm typecheck` passes
- [ ] `tours.json` names the new locale
- [ ] The intro and outro stills render in the new language with no fallback warning in the console
- [ ] Numbers and dates read correctly for the tag — formatting follows the BCP-47 tag, not the bundle
