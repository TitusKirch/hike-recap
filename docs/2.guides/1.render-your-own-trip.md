# Render your own trip

Everything the tool needs is a directory holding GPX files and a `tours.json` beside them. `HIKE_DATA_DIR` points ingest and the geodata fetch at it, so your tracks never sit next to the example and never end up in a commit by accident.

## Steps

1. **Create the directory and drop the tracks in.** Name each GPX by its date; the name is what `tours.json` refers to.

   ```text
   data.local/
     tours.json
     gpx/
       2026-08-07.gpx
       2026-08-08.gpx
   ```

   `data.local/` is already gitignored. Any other path works as long as you keep it out of the repo.

2. **Write `tours.json`.** [`data/tours.json`](../../data/tours.json) is a complete working example; the shape is documented in [`CLAUDE.md`](../../CLAUDE.md#data-model).

   ```jsonc
   {
     "title": "…",
     "region": "…",
     "locale": "en-GB", // names a bundle under locales/
     "attribution": [], // extra lines the built-in table cannot know
     "period": { "from": "2026-08-06", "to": "2026-08-24" },
     "tours": [
       {
         "id": "day-1-…", // kebab-case, stable
         "date": "2026-08-07",
         "title": "…",
         "gpx": "2026-08-07.gpx", // relative to gpx/
         "distanceKm": 11.0,
         "ascentM": 263,
         "descentM": 265,
         "durationMin": 227
       }
     ]
   }
   ```

   The four figures are what the video shows, and they come from this file rather than from the GPX — see [ADR-0004](../99.adr/0004-take-the-figures-from-tours-json-instead-of-the-gpx.md). The tour count lives here and nowhere else: the schedule, the viewport sequence and the route colours all follow from it.

3. **Fetch the geodata for your area.** It is derived from the GPX themselves, so there is nothing to configure. This is the only step that touches the network.

   ```bash
   HIKE_DATA_DIR=data.local pnpm fetch:geodata
   ```

4. **Ingest.** This writes `build/tours.compiled.json`, the one file the render path reads.

   ```bash
   HIKE_DATA_DIR=data.local pnpm ingest
   ```

   **Read the log rather than skipping past it.** It prints, per tour, the GPX distance against your figure and the DEM-derived ascent and descent against yours. Two warnings matter: a summit named in `tours.json` that is not in the OSM data, and `DEM ascent > 1.5 ×` your figure, which means the elevation smoothing is too weak for that terrain.

5. **Look at a frame before rendering 900 of them.**

   ```bash
   pnpm dev                 # the scene at http://localhost:5174
   pnpm still 200 900       # single frames into build/stills/
   pnpm render:preview      # the first 3 s
   ```

   Check a rendered frame, not just the preview: there is no system sans-serif in this environment, so an unloaded font falls back to a serif silently.

6. **Render.**

   ```bash
   HIKE_DATA_DIR=data.local pnpm render   # → out/hike-recap.mp4
   ```

   Roughly four and a half minutes at about 7 fps for the full reel.

## Checklist

- [ ] `tours.json` lists every GPX file, and every `gpx` value resolves to a file in `gpx/`
- [ ] `pnpm fetch:geodata` has been run at least once for this area
- [ ] The ingest log shows no missing-summit warning and no `DEM ascent > 1.5 ×` warning
- [ ] A rendered still shows the correct font, not a serif fallback
- [ ] The attribution strip in the outro names your area's sources, fits inside the frame, and no label sits on it
- [ ] `out/hike-recap.mp4` plays end to end, and your data directory is untracked
